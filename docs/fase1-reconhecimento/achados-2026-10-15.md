## 2. Combo correto do menu de serviço — EXL BR

Diferente da seção 4.1 do KB (que documenta `PRESET 1 + PRESET 6 + knob VOLUME` para LX): o Civic EXL BR **não tem presets físicos numerados nem knob de volume na central**. Os únicos controles físicos ao lado da tela são o botão **DAY/NIGHT** (ícone sol+lua, acima da tela) e os capacitivos **AUDIO ⏻ / HOME / + VOL − / MENU / BACK** à esquerda da tela.

**Combo que funciona no EXL BR:** `DAY/NIGHT + AUDIO + MENU` segurados por ~2 segundos, com carro em ON e áudio off. Confirmado em `fotos/07-self-diagnosis-mode.jpeg`. É o mesmo combo documentado no TSB Honda 17-049 (seção 4.3 do KB) — então **não é combo "da comunidade", é combo oficial Honda**.

Técnica para capacitivos + físico ao mesmo tempo: um dedo em cada capacitivo (AUDIO + MENU) e a outra mão apertando o DAY/NIGHT físico. Encostar firme no capacitivo, sem deslizar.

### Achado operacional

**O "Functional Setup" do EXL BR NÃO expõe dev mode / ADB.** A comunidade reporta essa rota para outras unidades Honda (ex.: CR-V 2016 sem navegação, seção 4.4 do KB). No EXL BR o Functional Setup só tem opções de reset de backup, trava DD, LaneWatch, Anti-Theft Skip e reprogramação de amp/display. **Essa rota está fechada aqui.**

## 4. Mecanismo do passcord — hipótese reformulada

**O que acontece:** no Settings do Android → Sobre o dispositivo → tocar 7 vezes em "Número da versão", aparece um toast curto `Please enter a passcord` (`fotos/03-passcord-toast.jpeg`). Note o typo "passcord" vs "passcode" — string única, serve de pivô para busca.

Tentada a sequência da XDA 2017 (`Modelo → Kernel → Android → Baseband`, ordem 1-4-2-3): **não funcionou**. Nenhum teclado apareceu, nenhuma tela nova — só o toast de novo.

**Hipótese nova, após o inventário de pacotes:** o passcord **não** destrava o dev mode do Android (como a XDA diz para unidades NA de 2017). Destrava os apps de serviço:

- `com.mitsubishielectric.ada.app.dealerdiag`
- `com.mitsubishielectric.ada.app.developerdiag`
- `com.mitsubishielectric.ada.app.preshipmentdiag`
- `com.mitsubishielectric.ada.app.letdiag`

Pistas que sustentam essa hipótese:

1. Existe um pacote dedicado `com.mitsubishielectric.ada.app.hidkeyboard` (**hidden keyboard** — teclado escondido). Quando a Mitsubishi quis um teclado só para serviço, criou um pacote inteiro.
2. O toast tem o typo "passcord" — mesma string que a XDA documenta para unidades 2017 (relato CivicX "In case anyone is wondering passcord for 2018 models"). Então o toast vem do mesmo módulo de validação Mitsubishi, e esse módulo foi mantido em 2016, 2017 e 2018 — se o passcord mudou entre safras, a mensagem continuou idêntica.
3. Nenhum dos relatos XDA realmente **habilita dev mode do Android com a sequência 1-4-2-3**. O que eles habilitam é "um menu adicional" acessado via `MENU` + `HOME` depois — provavelmente o `DealerDiag` ou `DeveloperDiag`.
4. O KB (seção 5) já aponta que o `/system` é read-only e o Android padrão não permite remontar; dev mode do Settings sozinho não escala para root. Dev mode Honda/Mitsubishi passa pelos apps `*diag`.

**Próxima rota de pesquisa (fora do carro, antes da próxima sessão):**
- Procurar `com.mitsubishielectric.ada.app.developerdiag` activity / intent → se achar o nome da activity, dá para disparar via `am start -n ...` **assim que** tivermos ADB (circular, mas vale mapear).
- Procurar o passcord correto para firmware da safra 2016-04 (`1.F187.16`). Não chutar.
- Avaliar rota via `com.honda.displayaudio.whitelist` (pacote Honda, não Mitsubishi — notado no pastebin de referência).
- Avaliar `com.mitsubishielectric.ada.app.systemupdate` — processo OTA pode abrir shell.
